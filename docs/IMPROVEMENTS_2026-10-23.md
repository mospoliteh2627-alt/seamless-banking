# Улучшения прототипа, 23.10.2026

## Что изменено

### 1. Двусторонний переход

Раньше сценарий был только web → mobile. Теперь мобильный клиент может:

- создать черновик кнопкой «Новый перевод»;
- пройти step-up;
- заполнить и отправить перевод;
- оставить черновик, который веб-клиент открывает из «Незавершённые операции».

Это усиливает главу 3: протокол проверяется в обе стороны, а не только в одну.

### 2. Процессная карта в мобильном клиенте

На главном экране появилась карточка:

- стадия (`Создана`, `Заполнение`, `Подтверждение`, `Переход`, `Исполнена`);
- прогресс 0–100 %;
- риск (`низкий` / `средний` / `высокий`);
- SLA (`SLA 1 ч 30 мин` или `SLA нарушен`).

Данные берутся из `GET /v1/processes`, то есть мобильный клиент использует ту же бизнес-модель, что веб и админка.

### 3. Живая timeline перехода на веб-клиенте

В модальном окне QR появилась timeline из четырёх фаз:

1. Билет выпущен.
2. Ожидаем телефон.
3. Step-up.
4. Черновик восстановлен.

Фазы переключаются по событиям `handoff.redeemed` и статусу билета. Это делает протокол видимым для комиссии, а не только для логов.

### 4. Анимированный Face ID / PIN на мобильном

Вместо стандартного диалога — нижний sheet:

- пульсирующие кольца сканирования;
- анимация Face ID;
- fallback на PIN-клавиатуру;
- haptic feedback;
- демо-PIN `0000`.

### 5. Время перехода на веб-клиенте

После события `handoff.redeemed` баннер показывает:

> Время перехода: 4,2 с.

Это измеряемая метрика для диссертации, а не декоративная надпись.

### 6. Избранные получатели

Добавлены:

- `GET/POST/DELETE /v1/recipients`;
- чипы избранных получателей на шаге 1 веб-клиента;
- горизонтальная лента на главном экране Flutter;
- сохранение получателя после перевода (чекбокс);
- дедупликация по счёту.

Это взято из практики Mifos/Fineract self-service: повторный перевод не должен требовать повторного ввода.

### 7. Надёжность демо и защита от дублей

- `scripts/demo.sh` — один запуск: API, health-check, открытие браузера, `.demo.pid`.
- `scripts/demo-stop.sh` — остановка.
- `Idempotency-Key` на submit: повторный запрос возвращает тот же чек, а не второй перевод.
- Дневной лимит `500 000 ₽` на сервере; превышение → `DAILY_LIMIT_EXCEEDED`.
- Клиенты web и mobile отправляют ключ идемпотентности.

### 8. Тесты

- `npm test` — 3 E2E-теста, все проходят.
- `flutter test` — 2 теста модели `ProcessInfo`.
- `flutter analyze` — 0 ошибок.
- `flutter build web --release` — успешно.
- `scripts/ui-flow.mjs` — полный сценарий web → mobile → submit, `UI flow OK`.

## Ограничения

- Новый перевод на мобильном использует демонстрационный step-up (`local-biometric`), не реальную биометрию.
- Процессная карта показывает первую активную операцию; список — ниже.
- Время перехода измеряется на клиенте от выпуска билета до события `handoff.redeemed`, включает задержку WebSocket.
