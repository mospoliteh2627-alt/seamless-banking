# Визуализация бизнес-процесса в интерфейсе

Задача — показать клиенту и сотруднику банка не набор форм, а управляемый процесс:
где операция находится, кто и когда её изменил, сколько времени осталось до SLA
и какой шаг будет следующим.

## 1. Модель процесса

| Стадия | Смысл | Условие |
|---|---|---|
| Создана | операция зарегистрирована | `createdAt` |
| Заполнение | введены или изменены поля | есть ввод / `step ≥ 1` |
| Подтверждение | клиент проверяет данные | `step ≥ 3` |
| Переход | черновик передан на другое устройство | `handoff.redeemedAt` |
| Исполнена | перевод отправлен | `status = submitted` |

Производные атрибуты:

- `progress` — 0…100 % по номеру стадии;
- `slaMinutes` — остаток до 24 ч с последнего изменения;
- `slaState` — `ok`, `at-risk` (< 3 ч), `breached`;
- `risk` / `riskLabel` — эвристическая оценка (сумма, шаг, handoff, остаток SLA).

## 2. Где видно

### Клиент

- **Карта процесса** на дашборде: пять стадий и количество операций на каждой.
- **Карточка операции**: стадия, шаг, сумма, риск, SLA, прогресс-бар.
- **Таймлайн в переводе**: пять точек с временем, активная стадия, SLA и риск.

### Сотрудник

- **Канбан** в `/admin`: пять колонок, карточки операций, риск и SLA.
- **Воронка**: начато → билет → handoff → отправлено.
- **Аудит**: кто, когда и что сделал, с проверкой hash chain.

### Мобильный клиент

- Компактная полоса стадий над формой: «Создана — Заполнение — Переход — Исполнена».
- После подтверждения активная стадия «Переход», после отправки — «Исполнена».

## 3. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/v1/processes` | процессы текущего клиента |
| GET | `/v1/admin/processes` | все процессы + статистика по стадиям |

Элемент процесса:

```json
{
  "id": "op_...",
  "stage": 3,
  "stageLabel": "Переход",
  "progress": 75,
  "slaMinutes": 1440,
  "slaState": "ok",
  "risk": 45,
  "riskLabel": "medium",
  "stages": [
    { "key": "created", "label": "Создана", "at": "...", "done": true }
  ]
}
```

## 4. UX-решения

1. **Одна метафора** — процесс, а не «черновик»: клиент видит путь операции.
2. **Прогресс важнее статуса** — полоса и стадии отвечают на вопрос «сколько осталось».
3. **SLA и риск** — сотрудник видит, какие операции требуют вмешательства.
4. **Единый словарь** — стадии называются одинаково в web, mobile и админке.
5. **Доступность** — статус дублируется текстом, а не только цветом; есть `aria-label`.

| Сервис | Что делает |
